# КРОК

Вебверсія: **[krok-theta.vercel.app](https://krok-theta.vercel.app)**. Розміщена у Vercel; ШІ-тренер працює в режимі закритого тестування.

Застосунок українською для щоденних квестів, звичок, цілей і контролю витрат. Тренер допомагає перетворити розмову на конкретні дії; запропоновані зміни спочатку показуються для підтвердження.

React 19, Vite 6, PWA, Capacitor 8, Supabase Auth і серверна інтеграція OpenAI. Репозиторій містить спільний інтерфейс, Android-оболонку та API-функції Vercel. Особисті фото, локальні ключі й матеріали розробки до нього не входять.

## Можливості та межі

- Квести, звички, цілі, витрати у гривнях, щоденник і прогрес персонажа.
- Текстовий тренер, диктування та добровільна почергова голосова розмова через доступні сервіси браузера. Це не OpenAI Realtime.
- Перегляд і підтвердження дій ШІ, керована пам’ять та незалежні згоди на передавання контексту.
- Короткі сценарії тренера: знайомство за дві хвилини (одна ціль і до трьох кроків), ранковий вибір головного та вечірній підсумок. Запитання ставить застосунок, до моделі йде один запит наприкінці.
- Добровільна синхронізація прогресу акаунта між пристроями через Supabase; працює без інтернету й надсилає зміни пізніше.
- Android-нагадування про справи з кнопками «Зробив», «Через 30 хв», «Сьогодні пропускаю». У браузері фонових push-сповіщень немає.
- Світле й темне оформлення, експорт/імпорт локальної резервної копії.
- Email/пароль через Supabase. Інтеграція Google передбачена, але потребує окремого налаштування; у шаблоні вимкнена.

**Прогрес зберігається на пристрої окремо для кожного акаунта: у localStorage браузера або приватному Preferences-сховищі Android.** Синхронізація вимкнена, доки людина не ввімкне її в «Акаунті» — окремо на кожному пристрої; сам вхід нічого не завантажує й не переносить. Після ввімкнення записи акаунта зберігаються одним документом у таблиці `krok_profiles` (доступ лише власника через RLS). Завантажене фото профілю не синхронізується. Якщо записи змінено на двох пристроях одночасно, КРОК не об’єднує їх, а питає, яку версію залишити. Локальний профіль можна скопіювати в акаунт лише після перегляду й підтвердження. Хмарну копію можна видалити; очищення даних браузера чи застосунку без синхронізації видаляє локальний прогрес, тож використовуй резервні копії. Токени входу не входять у копію прогресу.

Розміщений ШІ працює як закрита бета: потрібні підтверджена пошта Supabase і серверний список дозволених адрес. Довговічний облік звернень, ліміти на користувача, спільний бюджет і зупинка вмикаються окремою змінною (див. нижче). Оплати й тарифів немає. Звичайні локальні функції не потребують звернення до моделі.

## Локальна розробка

Потрібен Node.js 22 або новіший.

```sh
npm ci
npm test
npm run build
```

Для локального API скопіюй `.env.example` у `.env`, заміни потрібні значення й запусти:

```sh
node --env-file=.env scripts/serve.mjs
```

Готова вебзбірка й API доступні на `http://127.0.0.1:5177`. Якщо змінні вже задані в середовищі процесу, можна використати `npm start`; ця команда сама не читає `.env`.

В іншому терміналі:

```sh
npm run dev
```

Vite відкриває `http://127.0.0.1:5178` і передає `/api/auth` та `/api/coach` локальному API на 5177. Для розробки тренера потрібні обидва процеси. Порти 5177 і 5178 мають різні браузерні сховища. `npm run preview` перевіряє статичну збірку; він не замінює сервер API.

Локальний сервер прив’язаний до loopback і призначений для розробки. Серверна політика закритої бети описана нижче та застосовується окремим адаптером розміщення `scripts/deployment-api.mjs`.

## Vercel

Імпортуй репозиторій у Vercel. Налаштування в `vercel.json`: збірка `npm run build`, каталог `dist`, Node API-функції в `api/`. `src/`, `scripts/`, `public/`, `api/` і lockfile мають бути доступні під час збірки.

Android-джерела й локальні Windows-launchers не передаються у Vercel. Для Android встанови JDK/Android SDK, виконай `npm run android:sync`, потім `npm run android:open` для Android Studio або `npm run android:build`. Для фізичного телефона потрібен доступний HTTPS backend та відповідна конфігурація збірки; браузерне розгортання саме по собі не оновлює встановлений APK.

Додай змінні в налаштуваннях середовища Vercel, потім виконай нове розгортання:

| Змінна | Призначення |
| --- | --- |
| `SUPABASE_URL` | HTTPS URL власного Supabase-проєкту. Обов’язкова для розміщеного API. |
| `SUPABASE_PUBLISHABLE_KEY` | Публічний ключ `sb_publishable_...`; не secret/service-role. |
| `OPENAI_API_KEY` | Секретний API-ключ лише для серверних функцій. |
| `OPENAI_MODEL` | Необов’язковий ідентифікатор доступної моделі; значення за замовчуванням визначене сервером. |
| `KROK_ALLOWED_ORIGINS` | Точні HTTPS origins через кому, наприклад `https://your-project.vercel.app`. Без `*`, шляхів і query. Для власного домену додай його точний origin. |
| `KROK_AI_ALLOWED_EMAILS` | Адреси учасників бети через кому. Порожній список не дає доступу до платних запитів ШІ. |
| `KROK_GOOGLE_AUTH` | `false`, доки Google provider і callbacks не налаштовані та не перевірені. |
| `KROK_AI_USAGE` | Лише значення `enforce` вмикає довговічні ліміти ШІ в Supabase. Спершу застосуй міграцію `*_ai_usage.sql`; без неї ввімкнений режим закриває платні запити. |

Vercel також передає `VERCEL_URL` і `VERCEL_PROJECT_PRODUCTION_URL`: сервер додає саме ці deployment-hostnames до дозволених origins. Не підставляй origin із вхідного запиту та не відкривай довільні preview-домени wildcard-правилом. Для кожного дозволеного середовища окремо перевір налаштування Supabase.

**Не додавай `OPENAI_API_KEY` у `VITE_*`, клієнтський код, Git чи `public/`.** Публічні налаштування Supabase повертає `/api/auth/config`; OpenAI-ключ залишається на сервері. Відсутня або некоректна конфігурація розміщеного API блокує роботу відповідних запитів.

## Supabase і доступ до бети

1. У Supabase увімкни Email і підтвердження пошти. URL та publishable key доступні через **Connect** або **Settings → API Keys**.
2. У **Authentication → URL Configuration** встанови Site URL на фактичний production HTTPS origin. Додай точний redirect `https://your-project.vercel.app/?auth=callback`; для локальної розробки — `http://127.0.0.1:5178/?auth=callback` і `http://127.0.0.1:5177/?auth=callback`.
3. Для власного домену заміни приклад його реальною адресою. Не додавай непотрібні широкі wildcard. Лист підтвердження/відновлення відкривай у тому браузері, де почав дію: PKCE використовує локальний verifier.
4. Додай дозволені адреси до `KROK_AI_ALLOWED_EMAILS`. Сервер перевіряє bearer-сесію через Supabase й бере пошту та факт підтвердження з відповіді сервера, а не з даних клієнта. Анонімні акаунти не допускаються до платного ШІ.

### Таблиці Supabase

Виконай файли з `supabase/migrations/` у **SQL Editor** за порядком назв; їх можна запускати повторно.

- `*_profile_sync.sql` — таблиця `krok_profiles` для синхронізації. Клієнт працює з нею напряму сесією користувача й publishable key; RLS дозволяє кожному лише власний рядок, а тригер вимагає послідовну ревізію, щоб два пристрої не перезаписали одне одного.
- `*_ai_usage.sql` — облік звернень до ШІ: `krok_ai_limits` (один рядок із лімітами, цінами й перемикачем `paused`), `krok_ai_usage`, `krok_ai_usage_global` і функції `krok_ai_reserve` / `krok_ai_settle`. Сервер викликає їх токеном самого користувача; service-role ключ не потрібен. Значення лімітів за замовчуванням — заготовки: зміни їх у Table Editor. Зупинка всіх платних запитів: `update public.krok_ai_limits set paused = true;`

Межі цього обліку: день рахується за UTC; звернення зараховується, навіть якщо модель не відповіла; грошовий бюджет діє лише після внесення цін за токени; будь-який зареєстрований акаунт може викликати функції напряму й витратити частину спільного денного ліміту (не грошей), тому до відкритого запуску залишай список дозволених адрес або обмеж реєстрацію.

Google поки не є підтвердженим способом входу цього релізу. Для підключення створи OAuth client типу Web application у Google Auth Platform; його redirect — `https://YOUR_PROJECT.supabase.co/auth/v1/callback`. Client ID/Secret налаштовуються тільки в Supabase Google provider. Лише після перевірки потоку ввімкни `KROK_GOOGLE_AUTH=true`. Google-вхід сам по собі не дає підписку ChatGPT або кредити OpenAI.

## Перед публічним використанням

Перевір реальні Email confirmation/reset, ізоляцію акаунтів, точні origins і поведінку користувача поза beta allowlist. `/api/coach/status` показує наявність конфігурації; це не перевірка балансу або успішного платного запиту.

Без `KROK_AI_USAGE=enforce` технічні ліміти API працюють лише в пам’яті окремого теплого екземпляра функції й **не є розподіленим бюджетом**. Для ширшого запуску ввімкни довговічні ліміти, внеси ціни й бюджет, налаштуй власну пошту (SMTP) для листів підтвердження, погодь політику даних. Стандартна пошта Supabase надсилає листи лише на адреси учасників проєкту. Не представляй ШІ як медичну чи психологічну діагностику.
